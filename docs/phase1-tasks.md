# ขุนเงิน — Phase 1 Task List (MVP: Core Bill Splitting)

> อ้างอิง: `khunngern-prd.md` (F1.1–F1.6) และ `khunngern-roadmap.md` §5 · เขียนเมื่อ 2026-10-05
>
> หลักการแบ่ง: 1 task = 1 PR, ใช้เวลาประมาณครึ่งวันถึง 1 วัน, review ได้จบในรอบเดียว, มี "เสร็จเมื่อ" ที่เช็กได้จริง
> ทุก task อ้าง feature ID ใน commit / PR (เช่น `F1.3`)

## ภาพรวมลำดับ

```
M0 ตั้งโปรเจกต์ ─► M1 ตรรกะเงิน (pure) ─► M2 Webhook ─► M3 กลุ่ม + Registry ─► M4 สร้างบิล ─► M5 จัดการบิล ─► M6 ปล่อยใช้จริง
```

ทำไมเรียงแบบนี้:
- **ตรรกะคำนวณเงินมาก่อน** เพราะไม่ต้องพึ่ง LINE เลย เขียน test ได้เต็มที่ และเป็นส่วนที่พลาดไม่ได้ที่สุด
- **Webhook + Registry มาก่อน LIFF** เพราะฟอร์มสร้างบิลต้องมีรายชื่อสมาชิกให้ติ๊ก
- **ปล่อยทดสอบในกลุ่มจริงตั้งแต่ M3** (deploy เล็กๆ ไปเรื่อยๆ) ไม่ต้องรอจบ phase

Task ที่มี 🔀 ทำคู่ขนานกับ task ก่อนหน้าได้

งานที่ไม่ใช่โค้ด (สมัครบัญชี S01–S04, ออกแบบ D01–D06) อยู่ท้ายไฟล์ แนะนำให้เริ่ม S01–S03 และ D01 พร้อมกับ T01 เลย

## M0 — ตั้งโปรเจกต์

### T01 · สร้าง repo และโครงสร้างโปรเจกต์
- สร้าง GitHub repo (public), `.gitignore`, `LICENSE`, `README` สั้นๆ, `.env.example` (ชื่อตัวแปรเท่านั้น ไม่มีค่าจริง)
- โครง: `supabase/functions/` (webhook, liff-api), `supabase/migrations/`, `liff/` (หน้าเว็บ), `packages/core/` (ตรรกะเงิน ใช้ร่วมกัน), `packages/strings/` (ข้อความภาษาไทย)
- TypeScript strict, ESLint, Prettier
- **เสร็จเมื่อ:** clone มาแล้ว `lint` + `typecheck` ผ่าน

### T02 · CI บน GitHub Actions 🔀
- รัน lint, typecheck, unit test ทุก PR
- เปิด secret scanning / push protection ของ GitHub (กัน token หลุดเข้า repo public)
- **เสร็จเมื่อ:** PR ตัวอย่างขึ้นเช็กเขียว
- **ต้องมีก่อน:** T01

### T03 · รวบรวม credential เข้า secrets
- เอาค่าจาก S01–S03 ใส่ Supabase secrets และ GitHub secrets เท่านั้น (ไม่ commit ค่าจริง)
- จดชื่อตัวแปรทั้งหมดไว้ใน `.env.example`
- **เสร็จเมื่อ:** function ตัวอย่างอ่าน secret ได้, `git grep` ไม่เจอค่าจริงใน repo
- **ต้องมีก่อน:** T01, S01, S02, S03

### T04 · Database schema ของ Phase 1
- Migration: `group`, `member`, `bill`, `bill_share`, `processed_webhook_event` ตาม PRD §4
- เงินเป็น `bigint` หน่วยสตางค์ทุกคอลัมน์, `CHECK (amount > 0)`, index ตาม `group_id`
- ยังไม่ต้องสร้างตาราง Payment / Trip (ไว้ Phase 2/4)
- **เสร็จเมื่อ:** `supabase db reset` ในเครื่องผ่าน, มี seed ข้อมูลปลอม (ไม่มี userId จริง)
- **ต้องมีก่อน:** T01, T03

## M1 — ตรรกะเงิน (pure functions, test หนักๆ)

### T05 · Money utils — F1.3 🔀
- `parseBaht("100.5") → 10050`, ปฏิเสธทศนิยมเกิน 2 ตำแหน่ง, ค่าติดลบ, ศูนย์, ตัวอักษร
- `formatBaht(10050) → "100.50"` (มีคอมมาหลักพัน)
- ห้ามใช้ float กับเงินเด็ดขาด
- **เสร็จเมื่อ:** unit test ครอบ edge case ข้างบนครบ
- **ต้องมีก่อน:** T01

### T06 · Split calculation — F1.3
- `evenSplit(total, participants, ownerId, ownerShares)` → เศษสตางค์ไปที่ Owner ถ้า Owner ร่วมบิล ไม่งั้นไปคนแรกตามลำดับที่เข้าร่วม
- `validateCustomSplit(total, amounts)` → ผลรวมต้องเท่ายอดเป๊ะ ไม่งั้นคืน error ที่บอกว่าขาด/เกินเท่าไร
- **เสร็จเมื่อ:** test ตัวอย่าง PRD (100.00 / 3 → Owner 33.34, คนอื่น 33.33) ผ่าน + property test สุ่ม 1,000 ครั้งว่าผลรวม = ยอดเสมอ
- **ต้องมีก่อน:** T05

## M2 — Webhook พื้นฐาน

### T07 · Webhook Edge Function + ตรวจ signature
- รับ POST จาก LINE, ตรวจ `x-line-signature`, ตอบ 200 เร็ว, แยก event ตาม type ไป handler (ยังเป็น stub)
- **เสร็จเมื่อ:** test ว่า signature ผิด → 401, ถูก → 200; ตั้ง webhook URL ใน LINE console แล้ว "Verify" ผ่าน
- **ต้องมีก่อน:** T03, T04

### T08 · Idempotency
- บันทึก `webhookEventId` ลง `processed_webhook_event`, เจอซ้ำให้ข้าม (กันบิลซ้ำตอน LINE ส่ง event ซ้ำ)
- **เสร็จเมื่อ:** test ส่ง event เดิม 2 ครั้ง handler ทำงานครั้งเดียว
- **ต้องมีก่อน:** T07

### T09 · LINE client wrapper + strings layer 🔀
- ห่อ `reply`, `push`, `getGroupMemberProfile` ไว้ที่เดียว (นับจำนวน push ไว้ใช้ทีหลัง)
- `packages/strings`: ข้อความไทยทั้งหมดอยู่ในไฟล์นี้ ไม่ hardcode ใน handler
- **เสร็จเมื่อ:** handler เรียกผ่าน wrapper ได้, test ด้วย mock
- **ต้องมีก่อน:** T07

## M3 — กลุ่ม + Member Registry

### T10 · บอทเข้ากลุ่ม + ข้อความต้อนรับ — F1.1
- `join` → สร้าง/กู้คืน `group` (ถ้าเคยอยู่และข้อมูลยังไม่ถูกลบ), ส่ง Flex ต้อนรับ: แนะนำตัว, ปุ่ม "เข้าร่วมกลุ่มนี้", ปุ่ม "สร้างบิล", privacy notice 1 บรรทัด
- พิมพ์ `ขุนเงิน` / `ช่วยด้วย` → reply ข้อความเดียวกัน
- `leave` → ตั้ง `bot_left_at`
- **เสร็จเมื่อ:** เชิญบอทเข้ากลุ่มทดสอบแล้วเห็นการ์ด, เตะออกแล้วเชิญใหม่ข้อมูลยังอยู่
- **ต้องมีก่อน:** T08, T09

### T11 · Registry: ลงทะเบียนจากการทัก/กดปุ่ม/เข้ากลุ่ม — F1.5
- ทุก message / postback ในกลุ่ม → upsert ผู้ส่งเข้า `member`
- `memberJoined` → เพิ่ม, `memberLeft` → ตั้ง `left_at`
- postback "เข้าร่วมกลุ่มนี้" → ลงทะเบียน + reply ยืนยันสั้นๆ
- **เสร็จเมื่อ:** test ครบทุกช่องทาง, คนที่ `left_at` ไม่โผล่ในรายชื่อเลือกบิลใหม่
- **ต้องมีก่อน:** T10

### T12 · Registry: โปรไฟล์ + @mention — F1.5
- ดึงชื่อ/รูปจาก group member profile API, refresh ไม่เกินวันละครั้ง
- ลงทะเบียนคนที่ถูก @mention ในคำสั่งบอท (ถ้า LINE ให้ userId มา)
- **เสร็จเมื่อ:** ชื่อในฐานข้อมูลตรงกับชื่อใน LINE, mention แล้วคนนั้นเข้า registry
- **ต้องมีก่อน:** T11

> 🚀 **Deploy ย่อยครั้งแรก:** หลัง T12 ใช้งานบอทในกลุ่มทดสอบได้แล้ว (ต้อนรับ + จำสมาชิก)

## M4 — สร้างบิล

### T13 · Bill service (สร้างบิลในฐานข้อมูล) — F1.2
- `createBill(...)` ใน transaction เดียว: ตรวจยอด > 0, มี Member นอกจาก Owner อย่างน้อย 1 คน, ผู้ร่วมต้องอยู่ใน registry, Owner ร่วมบิล → share ของ Owner เป็น `paid_self`
- ใช้ T06 คำนวณ share
- **เสร็จเมื่อ:** test ทุก business rule ใน F1.2, ผลรวม share = ยอดบิลเสมอ
- **ต้องมีก่อน:** T04, T06

### T14 · Bill card (Flex) — F1.2
- แสดง ชื่อบิล, ยอดรวม, Owner, แต่ละคนต้องจ่ายเท่าไร + สถานะ
- ปุ่ม Phase 1: "เข้าร่วมบิลนี้", "สรุปยอด" (ปุ่ม "จ่ายแล้ว" / "ดูช่องทางโอน" ใส่ตอน Phase 2)
- **เสร็จเมื่อ:** snapshot test ของ JSON + ลองส่งเข้ากลุ่มทดสอบแล้วแสดงถูกทั้งบนมือถือและ PC, บิล 20 คนยังไม่ล้นการ์ด
- **ต้องมีก่อน:** T13

### T15 · Typed shortcut `บิล <ชื่อ> <ยอด> @...` — F1.2
- Parser ข้อความ → หารเท่ากันกับคนที่ mention (+ Owner ตามค่าเริ่มต้น "รวมฉันด้วย")
- พิมพ์ผิดรูปแบบ → reply วิธีใช้แบบน่ารักๆ
- **เสร็จเมื่อ:** test parser หลายแบบ (ชื่อมีเว้นวรรค, ยอดมีคอมมา, ไม่มี mention) + ลองในกลุ่มจริงแล้วได้บิลการ์ด
- **ต้องมีก่อน:** T12, T14
- หมายเหตุ: ทางนี้ทำงานได้โดยไม่ต้องมี LIFF ทำให้ทดสอบ flow สร้างบิลครบวงจรได้เร็ว

### T16 · LIFF API + การยืนยันตัวตน
- Edge Function `liff-api`: ตรวจ LIFF ID token กับ LINE, เช็กว่าผู้ใช้อยู่ใน registry ของกลุ่มนั้น
- ส่ง group ให้หน้า LIFF ผ่าน token สั้นๆ ที่บอทเซ็นไว้ใน URL ของปุ่ม "สร้างบิล" (เพราะ LIFF ไม่ได้บอก groupId มาให้เองแล้ว — อนุมานจากเอกสาร LIFF รุ่นใหม่ ต้องเช็กอีกทีตอนทำ)
- Endpoint: `GET members` (รายชื่อจาก registry), `POST bills`
- **เสร็จเมื่อ:** test ว่า token ปลอม/หมดอายุ/คนนอกกลุ่ม ถูกปฏิเสธ
- **ต้องมีก่อน:** T12, T13

### T17 · LIFF skeleton + deploy static host 🔀
- โปรเจกต์ `liff/` (Vite + TypeScript), `liff.init`, login, เรียก T16 ได้
- deploy ขึ้น static host ฟรี + ตั้ง Endpoint URL ใน LIFF app
- **เสร็จเมื่อ:** กดปุ่ม "สร้างบิล" ในกลุ่มแล้วหน้า LIFF เปิดและแสดงชื่อผู้ใช้
- **ต้องมีก่อน:** T03 (ทำคู่กับ T13–T16 ได้)

### T18 · ฟอร์มสร้างบิลใน LIFF — F1.2
- ช่อง: ชื่อบิล, ยอด, Owner (ค่าเริ่มต้น = คนสร้าง), ติ๊กผู้ร่วมจาก registry, toggle "Owner ร่วมบิล" (ค่าเริ่มต้น ON), หารเท่า/กำหนดเอง
- โหมดกำหนดเอง: แสดงยอดคงเหลือสดๆ, ปุ่มบันทึกกดไม่ได้จนกว่าผลรวมจะพอดี
- หลังบันทึก: ใช้ `liff.sendMessages` ส่งข้อความสั้นจากผู้ใช้เข้ากลุ่ม แล้วบอท **reply** การ์ดบิล (reply ฟรี ไม่กินโควตา push) จากนั้นปิดหน้า LIFF
- **เสร็จเมื่อ:** สร้างบิลทั้งแบบหารเท่าและกำหนดเองจากมือถือได้, การ์ดขึ้นในกลุ่ม
- **ต้องมีก่อน:** T14, T16, T17

### T19 · ปุ่ม "เข้าร่วมบิลนี้" — F1.2 / F1.5
- ลงทะเบียนคนกด + เพิ่มเข้าบิล
- บิลหารเท่า → คำนวณ share ที่ยังไม่จ่ายใหม่ทั้งหมด แล้ว reply การ์ดใหม่
- บิลกำหนดเอง → reply บอกว่าให้ Owner แก้บิลแทน
- กดซ้ำ → ไม่เพิ่มซ้ำ
- **เสร็จเมื่อ:** test ครบ 3 กรณี + ตรงกับ acceptance criteria ของ F1.5
- **ต้องมีก่อน:** T14

## M5 — สรุปยอด + แก้ไข/ยกเลิก

### T20 · สรุปยอด — F1.4
- คำสั่ง `สรุปยอด` / ปุ่ม "สรุปยอด" → reply รายคน: ยังค้างใครเท่าไร (เฉพาะ share ที่ยังไม่จ่าย, ไม่นับบิลที่ยกเลิก)
- แสดงต่อท้ายหลังสร้างบิลด้วย
- **เสร็จเมื่อ:** test กับหลายบิลหลาย Owner, ใช้ reply เท่านั้น
- **ต้องมีก่อน:** T13

### T21 · แก้ไขบิล — F1.6
- เฉพาะ Owner / Creator, เฉพาะตอนที่ยังไม่มีใครจ่าย
- เปิดฟอร์ม LIFF (T18) ในโหมดแก้ไข → คำนวณใหม่ → reply การ์ดใหม่ + ข้อความ "แก้ไขบิล"
- **เสร็จเมื่อ:** คนอื่นกดแก้ → ถูกปฏิเสธอย่างสุภาพ, Owner แก้แล้วยอดถูก
- **ต้องมีก่อน:** T18

### T22 · ลบ / ยกเลิกบิล — F1.6
- ยังไม่มีใครจ่าย → ลบได้; มีคนจ่ายแล้ว → ให้แค่ "ยกเลิกบิล" (สถานะ `cancelled`, เก็บประวัติ, ไม่นับในยอด)
- Phase 1 ยังไม่มีตาราง Payment → เขียนฟังก์ชัน `hasPayments(bill)` ที่ตอนนี้คืน `false` ไว้ก่อน Phase 2 ค่อยต่อจริง
- **เสร็จเมื่อ:** test ทั้งสองทาง (mock `hasPayments`), บิลที่ยกเลิกหายจากสรุปยอด
- **ต้องมีก่อน:** T20

- **เสร็จเมื่อ:** มี URL https สำหรับใส่เป็น LIFF Endpoint URL
- **ต้องเสร็จก่อน:** T17

## Labels บน GitHub

| Label | ใช้กับ |
|---|---|
| `type: code` | งานเขียนโค้ด |
| `type: setup` | สมัครบัญชี / ตั้งค่าบริการ ไม่มีโค้ด |
| `type: design` | ออกแบบหน้าตา การ์ด ฟอร์ม persona |
| `type: content` | เขียนข้อความภาษาไทย |
| `type: testing` | ทดสอบด้วยมือในกลุ่มจริง |
| `type: docs` | เอกสาร |
| `needs: Dear` | ต้องให้ Dear ทำเองหรือตัดสินใจ |
| `area: core` / `area: bot` / `area: liff` / `area: db` / `area: infra` | ส่วนของระบบ |
| `phase: 1` | ทุก issue ใน phase นี้ (และใช้ milestone "Phase 1 — MVP" ด้วย) |

## ค่าเริ่มต้นที่เลือกไว้ (เปลี่ยนได้)

- ปุ่ม "จ่ายแล้ว" / "ดูช่องทางโอน" ยังไม่ใส่ในการ์ด Phase 1 เพราะยังไม่มีระบบจ่าย (Phase 2)

- Rich Menu ยังไม่ทำ: Rich Menu แสดงในแชท 1:1 กับบอทเท่านั้น ไม่ช่วยในกลุ่ม
- Monorepo เดียว (bot + LIFF + core) เพื่อแชร์ตรรกะเงินและ type ร่วมกัน
